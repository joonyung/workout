# 개인 운동 운영체제 설계안

## 제품 정의

Workout OS는 단순 운동일지가 아니라 다음 순환을 유지하는 개인 훈련
운영체제다.

`프로필·환경 → Codex 계획 → PWA 수행 → 파일 기록 → Codex 리뷰 → 다음 계획`

PWA는 운동 중 빠르고 확실해야 하고, Codex는 운동 밖에서 데이터를 읽어
계획과 피드백을 갱신해야 한다. 두 역할 사이의 계약은 사람이 읽을 수 있는
JSON과 CSV 파일이다.

## 현재 데이터 해석

InBody 기록은 2020-10-16부터 2026-07-03까지 13회 존재한다. 최신 측정은
체중 69.2kg, 골격근량 33.1kg, 체지방량 10.5kg, 체지방률 15.2%,
인바디점수 79다.

2024-04-16 이후에는 체지방이 줄고 골격근량이 늘었지만, 2024-10-10부터
2026-07-03까지 골격근량은 33.1kg으로 동일하다. 이 구간을 개선하려면
InBody만 더 자주 보는 것보다 실제 운동의 중량, 반복수, RPE, 세트 수행률,
회복 상태가 누적되는지 확인해야 한다.

## 시스템 경계

### PWA가 담당하는 것

- 현재 프로그램 표시
- 컨디션 선택
- 세트별 중량, 반복수, RPE, 완료 체크
- 운동별 자동 휴식 타이머
- 세션 RPE와 메모
- 운동 기록, InBody 추세, 체육관 장비 확인
- 브라우저 즉시 저장과 로컬 파일 서버 동기화

### Codex가 담당하는 것

- 당일 운동 선택과 순서
- 세트, 반복 범위, 목표 RPE, 휴식 처방
- 장비 상태에 따른 대체 운동
- 최근 수행에 따른 중량·반복 진행 판단
- 주간 수행률과 정체 원인 검토
- 월간 프로그램 구조와 프로세스 업데이트
- 새 InBody를 장기 추세에 포함한 피드백

### 자동 계산이 담당하는 것

- 완료 세트와 수행률
- 기록된 총 볼륨
- 운동별 추정 1RM
- 부위별 세트 수
- 단순한 누락·정체 신호

자동 계산은 관찰값을 만든다. 프로그램 변경의 최종 판단은 Codex가 최근
기록과 사용자 상황을 함께 읽고 내린다.

## 데이터 흐름

1. 사용자가 앱 설정에서 프로필과 체육관 장비를 저장한다.
2. 서버가 이를 runtime `data/profile.json`과 `data/gyms/`에 저장한다.
3. Codex가 `npm run coach:context`로 최신 상태를 읽는다.
4. Codex가 날짜별 계획과 runtime `data/plans/current.json`을 만든다.
5. PWA가 현재 계획을 불러오고 작업 세션을 생성한다.
6. 세트 변경마다 브라우저에 즉시 저장하고 짧은 지연 후
   runtime `data/workouts/`에 같은 세션을 갱신한다.
7. 연결이 끊기면 브라우저 기록을 유지하고 재연결 시 세션 id와
   `updatedAt` 기준으로 병합한다.

## 계획 데이터 계약

당일 계획은 다음을 반드시 포함한다.

- 날짜와 고유 id
- 제목, 목표, 예상 시간, 훈련 단계
- 어떤 InBody와 몇 개의 운동 기록을 사용했는지
- 불완전한 정보에 대한 가정
- 컨디션별 수행 규칙
- 운동별 근육군과 장비 id
- 목표 세트, 반복 범위, RPE, 휴식
- 짧은 기술 큐와 대체 운동

계획을 갱신하면 날짜별 스냅샷과 current 파일은 완전히 같아야 한다.
`npm run validate:data`가 이를 확인한다.

## 운영 주기

### 매 운동일

- 운동 전: Codex에 가능한 시간과 특이 컨디션을 알려 프로그램 생성
- 운동 중: PWA에서 세트 기록, 자동 휴식, 장비·통증 메모
- 운동 후: 세션 RPE와 다음에 반영할 메모 저장

### 매주

- 최근 7일과 직전 3주 비교
- 수행률, 주요 운동 진행, 부위별 세트, 평균 피로 확인
- 다음 주에 바꿀 핵심 변수 하나 선택

### 매월

- 최근 4-6주의 수행과 회복 검토
- 프로그램 분할과 세션 길이가 생활에 맞는지 확인
- InBody 여러 측정과 운동 성과의 방향 비교
- 체육관이나 장비 변화 반영

## 구현 상태

- Apple 스타일 모바일 우선 PWA
- 당일 계획 파일 로드
- 세트 기록, RPE, 완료, 휴식 타이머
- 브라우저 즉시 저장
- 로컬 서버의 프로필·체육관·운동·InBody 파일 저장 API
- 운동 기록 병합과 오프라인 폴백
- InBody 단일 지표 추세 차트
- 주간 수행률, 볼륨, 추정 1RM
- 데이터 계약 검증과 핵심 계산 테스트

## 다음 단계

1. 실제 체육관 장비와 통증·부상 여부를 입력한다.
2. 2주 동안 실제 세션을 기록해 중량과 RPE 기준선을 만든다.
3. 기록으로 첫 주간 리뷰를 수행하고 초기 프로그램을 교정한다.
4. 외부에서도 항상 사용할 필요가 확인되면 인증된 HTTPS 배포와 서버
   저장소를 도입한다.
5. 이후 Apple Health 또는 운동 데이터 가져오기는 기록 누락을 실제로
   줄일 수 있을 때만 추가한다.
